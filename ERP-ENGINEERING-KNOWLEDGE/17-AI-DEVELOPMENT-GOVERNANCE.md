# 17 — AI-Assisted Development Governance

Future ERPs will be built mostly with Claude Code. This document turns BizDocs experience into enforceable rules. The repository-level rule file is `NEW-ERP-STARTER-KIT/CLAUDE.md`.

## 1. AI-related failures observed in BizDocs (verified)

| ID | What happened | Evidence | Rule |
|---|---|---|---|
| AI-01 | A fail-loud change applied app-wide without reviewing callers; reverted | `19ffca3` (AI co-authored) | R-AI-06 blast radius |
| AI-02 | Paste-ready SQL generated by a coding session would have double-credited stock and written a ledger-owned column; flagged before running; a second generated block would have overwritten the safe version | project notes, 18–19 Sept | R-AI-08 DB changes go through one reviewed path |
| AI-03 | A whole feature (factor-based unit reconcile) built before the business model was confirmed; then rejected | `c26783d` → `a874b57` | R-AI-05 no invented requirements |
| AI-04 | A fix made a DB function fire on every confirm instead of only on newly completed lines; caught in the implementation report | project notes 21 Sept | R-AI-07 report what changed in behaviour |
| AI-05 | Follow-up regressions within days: PR #97 after #95 (strike-offs), PR #100 after #99 (crash on every DC-return GRN page) | PRs #95/#97, #99/#100 | R-AI-09 render/DB tests before merge |
| AI-06 | Documentation claimed `npm run build` runs `tsc`; it does not, so "build passes" was weaker evidence than believed | CLAUDE.md §5 vs `package.json` | R-AI-01 evidence must be real |
| AI-07 | Owner reported shallow understanding and wrong instructions; demanded root-cause fixes applied consistently across all modules after reading repo docs | project notes 26 Nov | R-AI-02 discovery before change |
| AI-08 | Live DDL applied via tool without repo files | BD-F-029 | R-AI-08 |

Patterns that worked: separate discovery prompt and implementation prompt; governance docs read first; dry-run before commit; single-concern commits; owner merges.

## 2. Mandatory operating rules for Claude Code

| Rule | Claude must | Enforcement |
|---|---|---|
| R-AI-01 | Never claim completion without evidence: test output, query output, or screenshot pasted, not summarised. State explicitly what is unverified. | PR template check; reviewer |
| R-AI-02 | Read `CLAUDE.md`, `PROJECT-STATE.md`, and the module spec before changing code; run read-only discovery of the live schema/code paths touched | session start checklist |
| R-AI-03 | List affected modules, operations, reverse paths and dependencies (DEPENDENCY-MATRIX) before coding | PR template section |
| R-AI-04 | Never modify a test to make it pass unless the requirement changed; cite the FR/BR ID | CI diff check: test file changes require ID in commit |
| R-AI-05 | Never invent a business requirement; record open questions in REQUIREMENTS-REGISTER and stop for answer when it affects stock, money or security | reviewer |
| R-AI-06 | Before changing a guard, list every caller (grep / `pg_proc` search) and state the effect on each | PR template "blast radius" |
| R-AI-07 | Report behaviour changes explicitly ("now fires only when…", "now blocks when…") | PR template |
| R-AI-08 | DB changes only as migration files in the repo, applied by the agreed tool; destructive operations need explicit owner approval and inverse SQL | hook blocks `DROP`/`DELETE`/`TRUNCATE`/`UPDATE … ` without approval marker; CI drift check |
| R-AI-09 | Run the relevant tests (unit, DB, render) after implementation and include output | CI |
| R-AI-10 | No unrelated changes, no opportunistic refactors, no renames outside scope | diff review; max-files warning |
| R-AI-11 | Ask before significant architectural changes (new module, new pattern, change to posting function, new dependency) — record an ADR | reviewer |
| R-AI-12 | Search for existing functionality before adding (no duplicate helpers, hooks, functions) | reviewer; duplicate-code lint |
| R-AI-13 | No placeholders presented as complete: `TODO`, stubbed returns, "coming soon" must be listed in the session report | grep check in CI for new TODO/stub without ticket ID |
| R-AI-14 | Update PROJECT-STATE.md and SESSION-HANDOVER.md at the end of every session | session end checklist |
| R-AI-15 | Prefer deletion and simplification of repeatedly failing code over another patch (with the same gates) | reviewer |
| R-AI-16 | Default-off for any change to a daily workflow | reviewer |

## 3. Persistent project memory (survives compaction and new sessions)

Do not rely on Claude remembering previous conversations. The repository is the memory.

| File | Contains | Updated |
|---|---|---|
| `CLAUDE.md` (≤ 150 lines) | rules only; pointers to the rest | rarely, deliberately |
| `docs/PROJECT-STATE.md` | current phase, active work, what is done/verified, what is unverified, blockers | end of every session |
| `docs/SESSION-HANDOVER.md` | last session's changes, evidence, next step, open questions | end of every session |
| `docs/REQUIREMENTS-REGISTER.md`, `BUSINESS-RULES-REGISTER.md` | FR/NFR/BR/Q with status | when requirements change |
| `docs/adr/ADR-###.md` | architectural decisions | per decision |
| `docs/DATA-DICTIONARY.md` | tables, columns, single writer per derived value | with every migration |
| `docs/MODULE-SPECIFICATION/<module>.md` | states, transitions, operations, reverses, AC | per module |
| `docs/REGRESSION-REGISTER.md` | defect → test | per defect |
| `docs/RISK-REGISTER.md` | risks, acceptances | as needed |
| `CHANGELOG.md` | released behaviour changes | per release |

Session start: read CLAUDE.md → PROJECT-STATE → SESSION-HANDOVER → relevant module spec. Session end: update PROJECT-STATE and SESSION-HANDOVER with evidence.

## 4. Converting instructions into automated controls

| Instruction | Automated control |
|---|---|
| "Don't write stock from the client" | lint rule on client code: no insert/update to ledger/balance tables; DB grants deny it |
| "Fail loud" | lint for clamps; DB CHECK constraints |
| "Paginate" | lint: list calls must use the shared helper |
| "Schema in repo" | CI fresh-build + schema diff against staging/production |
| "RLS on every table" | CI schema lint + advisor |
| "Run tests" | CI required checks; branch protection |
| "Evidence for done" | PR template required sections; CI fails if empty |
| "No destructive SQL without approval" | Claude Code PreToolUse hook rejecting destructive SQL commands unless an approval token is present |
| "Don't edit tests to pass" | CI rule: changed test files require a requirement ID in the commit message |
| "Update project state" | Stop hook reminding/blocking if PROJECT-STATE.md unchanged after code changes |

Example hooks are in `NEW-ERP-STARTER-KIT/rules/claude-hooks.example.json`.

## 5. Division of labour (pattern that worked; adapt)

| Who | Does |
|---|---|
| Owner | decisions, sign-off on destructive changes, merges, customer contact |
| AI session (design/DB) | discovery queries, model, migration drafts, dry-runs |
| AI session (code) | implementation from an approved prompt, tests, PR with evidence |
| CI | enforcement of everything automatable |

Always issue a **discovery prompt first** (read-only, produces a findings report), then a **separate implementation prompt** that references the report.
